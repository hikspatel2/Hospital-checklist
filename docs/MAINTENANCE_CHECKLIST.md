## 1. Routine Operational Schedule

To ensure uninterrupted uptime, operational reliability, and clinical safety compliance, the hospital IT administration must adhere to the following maintenance cadence:

### Daily Checklist (5 Minutes)
* [ ] **Verify Cron Job Execution**:
  * Check `storage/logs/cron_schedules.log` to confirm daily inspection schedules were generated.
  * Check `storage/logs/cron_backup.log` to confirm the 02:00 AM daily backup succeeded.
* [ ] **Review Emergency Complaints**:
  * Check for any unassigned `Emergency` priority complaints in the Complaints Dashboard.
* [ ] **Check Application Error Logs**:
  * Inspect `storage/logs/app.log` for any unexpected `[CRITICAL]` or `[ERROR]` entries.

### Weekly Checklist (15 Minutes)
* [ ] **Storage Disk Space Audit**:
  * Review disk consumption in Hostinger hPanel File Manager.
  * Ensure `storage/backups/` and `storage/uploads/` are well within disk quotas.
* [ ] **Verify Backup Retention**:
  * Verify that `storage/backups/` contains no more than 7 daily archives. Older archives should have been pruned automatically by `scripts/cleanup_backups.php`.
* [ ] **Off-Site Backup Synchronization**:
  * Download the latest weekly `.tar.gz.enc` encrypted archive to secure offline or institutional cloud cold storage.
* [ ] **SLA Breach & Complaint Resolution Review**:
  * Export weekly complaint SLA report to evaluate departmental response times.

### Monthly Checklist (30 Minutes)
* [ ] **Isolated Disaster Recovery Test**:
  * Execute the isolated test restore CLI runner:
    ```bash
    php scripts/test_restore.php
    ```
  * Confirm that all table schemas and records match the expected integrity checksums.
* [ ] **Active Account Audit**:
  * Review all user accounts with `admin` and `supervisor` roles.
  * Deactivate credentials for any staff members who have resigned or transferred.
* [ ] **Physical Ward QR Poster Inspection**:
  * Check that physical QR code posters mounted in hospital wards remain legible, undamaged, and securely affixed.

### Quarterly Checklist (1 Hour)
* [ ] **Database Health & Table Optimization**:
  * Run table status checks and defragmentation if required via phpMyAdmin or MySQL CLI:
    ```sql
    OPTIMIZE TABLE `inspections`, `inspection_results`, `complaints`, `audit_logs`, `attendance_logs`;
    ```
* [ ] **Environment Pre-Flight Re-Audit**:
  * Run `php scripts/deploy_check.php` to confirm all server settings, PHP extensions, and permissions remain compliant.
* [ ] **Security Review**:
  * Audit `audit_logs` for abnormal login patterns, failed authentication spikes, or unauthorized privilege attempts.

## 2. Disk Space & Storage Quota Management

All dynamic files generated by the application reside exclusively within the `storage/` directory:

| Path | Contents | Retention Rule | Cleanup Method |
|---|---|---|---|
| `storage/backups/` | Encrypted MySQL dumps & full `.tar.gz.enc` archives | 7 Daily, 4 Weekly, 3 Monthly | Automated via `cleanup_backups.php` |
| `storage/logs/` | Application, cron, and error logs | 30 Days rolling | Rotated automatically by `Logger.php` |
| `storage/uploads/` | Uploaded evidence photos and PDF documents | Permanent operational evidence | Manual archiving if disk limit reached |
| `storage/temp/` | Temporary CSV exports and staging restore dumps | 24 Hours | Auto-cleaned on script termination |

> **Warning**: Never delete the `.htaccess` file located inside `storage/`. It prevents unauthorized web visitors from downloading hospital logs, backups, or evidence files.

## 3. Secret Rotation Procedures

### Rotating Database Credentials (`DB_PASSWORD`)
1. Create or change the MySQL user password in Hostinger hPanel (**Databases** > **MySQL Databases**).
2. Open `/home/u123456789/hospital_app/.env` with file permissions `0600`.
3. Update `DB_PASSWORD="<new-password>"`.
4. Test connectivity immediately:
   ```bash
   php scripts/deploy_check.php
   ```

### Rotating Backup Encryption Key (`BACKUP_ENCRYPTION_KEY`)
1. Generate a new cryptographically random 32-character key:
   ```bash
   php -r "echo bin2hex(random_bytes(16));"
   ```
2. Update `BACKUP_ENCRYPTION_KEY="<new-key>"` in `.env`.
3. **Crucial**: Existing backups remain encrypted with the previous key. Store old encryption keys in the hospital's secure IT password vault alongside the archives they encrypt.
4. Generate a new baseline backup using the new key:
   ```bash
   php scripts/backup.php database_only
   ```

## 4. Emergency Incident Response & Downtime Runbook

### Incident A: Database Connection Error (`SQLSTATE[HY000] [2002]`)
* **Symptom**: Web pages show *"Service Temporarily Unavailable"* or error logs report connection refused.
* **Troubleshooting Steps**:
  1. Check Hostinger MySQL service status in hPanel dashboard.
  2. Confirm database user has not exceeded maximum concurrent connections.
  3. Verify `DB_HOST`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in `.env`.
  4. Run `php scripts/deploy_check.php` to identify specific connection error codes.

### Incident B: Corrupted Upload or Disk Quota Exceeded
* **Symptom**: Photo uploads during inspection submission fail with HTTP 500 or permission denied.
* **Troubleshooting Steps**:
  1. Check disk usage via hPanel File Manager.
  2. If disk is at 100%, delete old files from `storage/temp/` or move older `.tar.gz.enc` backups to external storage.
  3. Verify folder permissions:
     ```bash
     chmod -R 750 storage/
     ```

### Incident C: Accidental Deletion of Critical Data
* **Symptom**: Ward, checklist, or complaint mistakenly deleted by an operator.
* **Recovery Steps**:
  1. Check if the record was merely soft-deleted (`deleted_at IS NOT NULL`). An Administrator can restore soft-deleted records from the Trash / Inactive view in the Admin UI.
  2. If hard-deleted, locate the latest backup in `storage/backups/`.
  3. Run `php scripts/test_restore.php` in isolated staging to verify integrity.
  4. Perform selective restoration of the affected table as outlined in [DISASTER_RECOVERY.md](file:///d:/hospital%20php%20website/docs/DISASTER_RECOVERY.md).
